## One actual-owner prepare/confirm

After the accepted source producer and protected native registration exist, the actual
human owner calls POST `/api/bots/contact-verification/enrollment/prepare` with exact
registrationId, reads the full current registration and source manifest, then confirms
POST `/confirm` with registrationId/enrollmentHash. Native independently fetches again
and records an immutable technical enrollment only if the hashes/current access match.
The two-target packets require independently exact registrations; copying one cannot
complete the other. This is technical trust, not outreach or financial approval.

The original owner can then use `prepare_contact_verification` to read the current
public template pair. Only after executable setup and that exact manifest exist can
actual outreach authorization be requested through a new exact structured proposal.
This build asks for no outreach approval. Source public redemption and all later
contact-proof association/consumption remain separately governed.
