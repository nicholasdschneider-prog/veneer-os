Strict DTO source of truth: server/src/bots/caseCustodyContract.ts. All hashes use SHA256 of recursive ordinal-key sorted JSON `{domain,value}` (native canonicalSha256). Exact source case versions/event timestamps are opaque strings, never JS-Date rounded. Historical nulls, event ID/hash, foreign principal and unbound chronology are preserved.

Dedicated source reads (separate approved reader custody, pinned origin, no query/redirect/fallback, bounded1MiB/10seconds): GET `/api/cs/custody/evidence/:caseId` → case-custody-evidence/v1; GET `/api/cs/custody/intents/:sourceRequestId` → case-custody-intent/v1. Service proof binds every registration/business/account/runtime field; evidence snapshotHash uses `case-custody/evidence/v1` over all fields except observedAt/expiresAt/snapshotHash. Freshness <=15seconds. Scope only prospective completed-case custody, not reopen/send/refund or historical same-owner repair.

Historical origin enrollment is `historical_only`, supported by genuine immutable identity evidence. Retired may be true; it grants no current actor rights and must not be reactivated. Destination must be active_destination, not retired/revoked, and independently match the original native executor binding. Unknown identity evidence, incomplete coverage, current material blockers or UNKNOWN prior effects deny. Source enrollment assertions must be authenticated by the separately accepted service, not supplied by a bot.

Native authenticated reviewer inspect/issue APIs read complete bounded native direct human messages and result replies/anchors in the enrolled reviewer's original chat. Human authorship/current owner access is authenticated; semantic review cites every human message and exact prior-effect revision. No keywords, detached hash or bot commission creates consent. Human enrollment of dedicated technical trust is not issuance consent. Only an actual unconditional current human custody instruction, interpreted through complete accountable review, can support prospective issuance. Omitted attachments/media/source context must block, not count as reviewed.

Service GET `/api/case-custody/verifier/authorities/:id` is exact-only and nonexecuting. POST `/claims` consumes strict case-custody-claim/v1 once. Source must durably store PREPARED intent then CAS REDEEMING BEFORE native claim, including native immutable authority/hash, exact original request hash and redemption requestKey. Native independently reads persisted intent and fresh case evidence, then revalidates native context/trust/revocation in an immediate SQLite transaction. First response alone has custodyEntitlement:true, execute:false. All read/replay responses false. GET `/claims/:authorityId` reconciles exact durable native reservation, never entitlement. POST `/receipts/:authorityId` accepts no caller receipt payload and fetches the authenticated original source intent.

Native claim wins before revoke => irreversible reservation, revocation cannot cancel or regrant it. Revoke wins => claim denied. Expiry/revocation/UNKNOWN/local rollback never frees original unique registration+case+completion event. Source must retain unique authority and request identities, serialize all relevant custody writers and persist exact audit/claim correlation. Source local rollback after claim remains terminal/UNKNOWN; read-only same-key reconciliation cannot run another mutation even if no effect is proven. APPLIED receipt must bind original claim and immutable source receipt hash. UNKNOWN may later reconcile to a verified APPLIED/ROLLED_BACK_TERMINAL outcome; conflicting terminal receipts deny. No distributed atomicity or post-claim revocation guarantee.

Default unavailable: no protected registry installed, no human enrollment, no source consumer acceptance, no live issuance/adoption/mutation. Dedicated CF audience/client, bearer commitment, reverse reader custody, authentic historical enrollment and current destination enrollment must be established by rightful owner/custodian, never reuse SMS/return/routine trust. ## Complete routes and response contracts

Human/native authenticated paths under `/api/bots/case-custody`:
- POST `/enrollment/prepare` {registrationId,caseId}, actual human business owner only; authenticated source identity observation, nonexecuting.
- POST `/enrollment/confirm` {registrationId,caseId,enrollmentHash}, same human only; re-fetches exact evidence and stores immutable technical enrollment, never custody authority.
- POST `/inspect` inspectionInput → inspectionResponseSchema; original reviewer only, execute:false/authority:false.
- POST `/issue` issueInput → issueResponseSchema; execute:false/custodyEntitlement:false, immutable prospective authority or identical replay.
- GET `/authorities/:id` → readResponseSchema; original reviewer/executor or actual owner, no source call or renewed entitlement.
- POST `/authorities/:id/revoke` {reason} → revokeResponseSchema; original reviewer or owner, reserved claim remains irrevocable.

Dedicated service paths under `/api/case-custody/verifier`, no query parameters:
- GET `/authorities/:id` → exportResponseSchema with <=15second observation bounded by authority/source expiry, never renewed underlying expiry.
- POST `/claims` claimInput → claimResponseSchema; first-only custodyEntitlement:true requires nonnull durable claim, all responses execute:false.
- GET `/claims/:authorityId` → claimReconciliationSchema, literal custodyEntitlement:false including null/no claim. Every actual summary includes claim ID, authorityId/hash, sourceRequestId/hash, requestKey and createdAt.
- POST `/receipts/:authorityId` strict empty body → receiptResponseSchema; independently authenticated source readback only.

Dedicated transport: X-Case-Custody-Registration-Id, own bearer matched by SHA256, dedicated CF Access service JWT audience/common_name (no human JWT). Never arbitrary audience header. Native reader uses only owner-enrolled dedicated CASE_CUSTODY_* credential reference at use time to pinned source GETs. No source adapter trust copied from SMS/return/routine. Registry service policy is available only after matching immutable human enrollment and current business owner/reviewer/executor access. Source accepted implementation and custody receipts are required commitments, not inferred from presence of fields.

Hash domains: `case-custody/evidence/v1` excludes only evidence observedAt/expiresAt/snapshotHash; `case-custody/transition/v1` commits entire transition; `case-custody/authority/v1` commits all authority fields except authorityHash; `case-custody/context/v1` commits complete native surfaces+owner/reviewer/executor/registration hash; `case-custody/instruction/v1` commits exact authenticated native source+anchor; `case-custody/review/v1` commits complete review INPUT; `case-custody/inspection/v1` commits exact input+registration/context/instruction/source-evidence hashes; `case-custody/enrollment/v1` commits entire registration+authenticated from/to enrollments.
