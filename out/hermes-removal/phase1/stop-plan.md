The commands below use this PowerShell function. It opens the single current definition exclusively, refuses ambiguous IDs or nonboolean enabled fields, changes only the selected enabled value semantically, and re-reads that field. It serializes JSON formatting, retaining all other parsed fields. Acquire the same runtime/definition ownership used by the scheduler before applying; if scheduler ownership cannot be established or the exclusive open fails, defer that item. No helper is installed on the PC. Do not apply this to historical copies.

```powershell
function Set-HermesCronEnabled {
    param([string]$Path, [string]$Id, [bool]$Enabled)
    $stream = [IO.File]::Open($Path, [IO.FileMode]::Open,
        [IO.FileAccess]::ReadWrite, [IO.FileShare]::None)
    try {
        $reader = [IO.StreamReader]::new($stream, [Text.Encoding]::UTF8, $true, 4096, $true)
        try { $document = ConvertFrom-Json -InputObject $reader.ReadToEnd() }
        finally { $reader.Dispose() }
        $jobs = if ($null -ne $document.jobs) { @($document.jobs) } else { @($document) }
        $matches = @($jobs | Where-Object { $_.id -eq $Id })
        if ($matches.Count -ne 1 -or $matches[0].enabled -isnot [bool]) {
            throw 'Expected exactly one job with a boolean enabled field'
        }
        if ($matches[0].enabled -eq $Enabled) { throw 'State changed; re-inventory before acting' }
        $matches[0].enabled = $Enabled
        $json = ConvertTo-Json -InputObject $document -Depth 100
        $bytes = [Text.UTF8Encoding]::new($false).GetBytes($json + "`n")
        $stream.Position = 0
        $stream.Write($bytes, 0, $bytes.Length)
        $stream.SetLength($bytes.Length)
        $stream.Flush($true)
    } finally { $stream.Dispose() }
    $check = ConvertFrom-Json -InputObject ([IO.File]::ReadAllText($Path))
    $checkJobs = if ($null -ne $check.jobs) { @($check.jobs) } else { @($check) }
    $selected = @($checkJobs | Where-Object { $_.id -eq $Id })
    if ($selected.Count -ne 1 -or $selected[0].enabled -ne $Enabled) {
        throw 'Enabled state readback failed; do not retry blindly'
    }
}
```

A write failure can leave a damaged JSON file; no bulk edits or automatic retries are permitted. Establish a non-secret, approved configuration recovery checkpoint first. No credentials are to be copied as part of the checkpoint.
